# Connectors

Trusted TypeScript modules implement id/version/capabilities, validateConfig, testConnection and collect. HEALTH does not grant EXECUTION. HTTP health is active from Phase A. Phase B adds a real normalized backup-result webhook, configured separately per policy in Sources; it receives completed results but does not collect from a backup product or execute operations. Prometheus metrics, product-specific backup connectors, dedicated TLS monitoring and controlled execution remain future work.

Configure a target in Monitoring as an admin, then a check against a resource. Exact hostname/IP or explicitly allowed CIDR plus port is required. Private/loopback access needs the per-target private flag. Link-local, unspecified, multicast, reserved and metadata IPs remain blocked even with that flag. DNS resolves all addresses before the request; every address must pass policy, and the connection uses the selected IP through a fixed lookup callback. Redirects are not followed. TLS certificate validation remains enabled. No response bodies are stored. Optional Authorization is encrypted with AES-GCM; only its scoped secret reference is in the check. Worker decrypts it locally and never includes it in observations, UI or exports.

Timeout is bounded, method GET/HEAD only, status expectations explicit. Latency measures an actual request to response headers. HTTP success ratio is a ratio of observed checks, not a precise time-based SLA. Results expire after three intervals. Failure/recovery thresholds deduplicate incident transitions; maintenance suppression is independent of observed health.

The implemented backup webhook contract is in `openapi.yaml`, with setup and limitations in [phase-b.md](phase-b.md). A per-connection encrypted AES-256-GCM HMAC key, timestamp window, externalRunId receipt and workspace/policy binding are mandatory; admin/API Bearer tokens are not accepted. Alertmanager is not implemented. No connector was automatically configured against corporate systems.
