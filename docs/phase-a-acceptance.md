## Что Подключено На Самом Деле

- PostgreSQL хранит реестр, авторизацию, аудит, историю и артефакты.
- Redis/BullMQ обслуживает настоящие worker jobs и повторные попытки.
- HTTP/HTTPS adapter выполняет реальные разрешённые запросы с SSRF-защитой и TLS-проверкой.
- XLSX/CSV parser, ExcelJS и Playwright Chromium реально импортируют и создают файлы.
- Скрипт metadata backup работает с PostgreSQL InfraDeck.

Домены, endpoints, провайдеры, характеристики серверов, расходы, политики бэкапов, backup/restore results, версии ПО и roadmap являются ручным учётом. Статус Manual или declared YES не подтверждает автоматизацию. Ссылка приглашения передаётся вручную; SMTP-интеграции нет. S3 в реестре не является подключением к S3 API.

## Порядок Ручной Приёмки

1. Установить чистый экземпляр по README, завершить setup и войти. Проверить пустой реестр и отсутствие default/demo-аккаунтов.
2. Создать два синтетических проекта и общий ресурс, заполнить typed details, expense и allocation. Сравнить dashboard и карту.
3. Архивировать проект, открыть архив, удалить его по имени. Проверить сохранность общего ресурса и второго проекта.
4. На ресурсе создать disabled/enabled check, ручную политику с schedule и незавершённую работу. Проверить блокировки, затем отключить/завершить их и удалить ресурс. Проверить связи, аудит и /deletion-history.
5. Пройти project/direction imports с явным разрешением связей. Повторный commit не создаёт дубликатов.
6. Передать приглашение без SMTP, проверить email/expiry/revoke/replay. Создать токен, вызвать разрешённый и запрещённый endpoint, отозвать токен.
7. Загрузить логотип, создать PDF/XLSX, проверить стоимость по проектам и отсутствие baseline без старых данных. Удаление объекта не меняет уже созданный файл.
8. Переключить RU/EN, пройти формы клавиатурой, проверить длинное название на desktop/mobile. Перезапустить web/worker и проверить сохранность данных.

Автоматическая проверка: `npm.cmd run build`, затем `npm.cmd run test:phase-a`. Прогон создаёт собственную временную БД и queue namespace, проверяет миграции, пустую установку, 17 тестов и три E2E-сценария (включая первый webhook фазы B). Результаты финального прогона фиксируются в implementation-status.md; эта таблица не заменяет проверку выбранной установки.

Автоматическая инициализация OWNER в чистом Docker: `npm.cmd exec -- tsx scripts/compose-acceptance.ts --initialize-admin`. Используется отдельная синтетическая установка: проверяются реальный вход, закрытие setup, повторный запуск без сброса аккаунта и отсутствие INIT credentials в web/worker.

Проверка чистого Docker setup: после `docker compose build` выполнить `npm.cmd exec tsx scripts/compose-acceptance.ts`. Проверка использует отдельный Compose-проект, PostgreSQL volume и порт 3002; подтверждает пустую установку, готовность worker и PDF внутри контейнера, затем убирает только свои контейнеры/volume. Финальный прогон прошёл. `.env` и оба файла тестовых credentials отсутствуют в Git и production-образах web/worker/migrate. При обновлении текущего экземпляра сохранность существующих записей подтверждена сравнением counts до/после; metadata backup успешно восстановлен в отдельную БД.
