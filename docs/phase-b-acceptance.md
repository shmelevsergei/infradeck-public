# Приёмка фазы B

Область: B1/B2/B3 из [roadmap](roadmap.md), дополнительные TLS-проверки исходной B.
Инструкция: [user-guide](user-guide.md). Наличие кода коннектора не означает,
что текущая установка подключена к реальным серверам или каналам.

| Функция | Что доступно | Ручная проверка | Статус / границы |
| --- | --- | --- | --- |
| Проектные назначения | OWNER/ADMIN назначают VIEWER/OPERATOR проекты и область доступа | Пригласить project-only VIEWER, назначить проект, войти; открыть чужой URL, отчёт и /access | Работает; ограниченный портал вместо общего console. Проектный экспорт пока запрещён |
| Проектный OPERATOR | Подтверждение доступных инцидентов | VIEWER отказ; OPERATOR общего сервера должен иметь права во всех его проектах | Работает; не выдаёт SSH/S3 или право менять инфраструктуру |
| Бюджеты | Ручной месячный лимит, валюты, расчётные расходы/остаток, audit и optimistic version | Распределить общий счёт 40/60, задать бюджеты, изменить/удалить | Работает; оценка по ставкам/датам, не факт оплаты; UTC-месяц, без FX |
| Prometheus | CPU/RAM/disk/inodes/load/iowait/RX/TX, последние сводки, реальная история 1–168h | Настроить exporter/Prometheus, разрешить цель, привязать job/instance; отключить источник | Работает с совместимым API; синтетический HTTP-контракт проверен. Реальный источник текущей установки не подключён |
| Свежесть | UNKNOWN/PARTIAL/STALE, отдельный отказ сбора | Удалить ряд, остановить источник, дождаться TTL | Работает; отсутствие ряда не закрывает прежний инцидент |
| Правила | Длительность превышения, hysteresis/recovery, severity, silence с expiry, bounded reminders | >70% диска 15 min; восстановление <65% 10 min; подавление; пропуск данных | Работает; новые правила создаются явно. Профиль не включает все дополнительные метрики roadmap |
| TLS expiry | Отдельный hostname/port, проверенная цепочка/имя, warning/critical, maintenance | Согласованная тестовая TLS-цель с коротким сроком, затем исправить | Реализовано; lifecycle/threshold/UNKNOWN проверены с изолированным collector, allowlist отказывает до сети. Живая внешняя TLS-приёмка ещё нужна |
| Alertmanager | Scoped expiring Bearer hash, one-time secret, revoke, dedupe/out-of-order | Отправить firing/resolved и повтор; другой job/instance отказ; отзыв | Работает; DB/HTTP-контракт, повторы/права проверяются тестами |
| Email | SMTP 465 TLS / 587 mandatory STARTTLS, проверка сертификата | Свой тестовый SMTP, явная тестовая отправка, проверить ящик | Отправитель реализован; реальная доставка без согласованного SMTP не проверена |
| Telegram | Bot API, encrypted token, тест из UI | Разрешить api.telegram.org:443, отправить тест и подтвердить получение в чате | 22.10.2026: Telegram принял тест (SENT), пользователь подтвердил получение. Принят один настроенный канал; полный цикл инцидент/восстановление/отказ ещё отдельно |
| Discord | Incoming webhook, без raw-secret readback | Разрешить discord.com:443, отправить тест | Отправитель реализован; реальная доставка пока не проверена |
| Маршрутизация и outbox | Проект/type/severity, event dedupe, grouping, retries/429, FAILED/retry, отмена | Ошибка sender, Retry-After, параллельная обработка, отзыв канала/привязки | Работает; внешняя доставка at-least-once, не обещает прочтение/exactly-once |
| HTTP/backup/budget signals | Отказы/восстановление HTTP, FAILED webhook, opt-in backup freshness, 80/100% бюджета | Включить freshness, просрочить SUCCESS; изменить бюджет; отключить канал | Реализовано; webhook не исполняет бэкапы. Отдельное выполнение C2 описано в backups-s3.md и не закрывает внешнюю приёмку B |
| Отчёты/история/удаление | Новые snapshots бюджетов/метрик; явные блокеры и historical preservation | Отключить проверки/каналы, удалить синтетический проект/ресурс; скачать старый отчёт | Работает по deletion.md; secret ciphertext не включается в historical export |
| Product-specific backup/cloud connectors | Выбор продукта и контракт | Назвать backup engine/provider и согласовать тестовый API | Не реализовано, ожидает выбора продуктов; универсальный webhook не заменяет коннектор |

## Автоматические проверки

22.10.2026: пользователь подтвердил получение реального тестового Telegram
сообщения после исправления точного workspace allowlist. Это закрывает smoke-test
доставки этого канала, но не всю B: внешние Prometheus/TLS/SMTP/Discord/Alertmanager
и полный сценарий инцидент → уведомление → восстановление остаются открытыми.

Итог 21.10.2026: typecheck, lint, production/Docker build, 11 clean migrations,
19 domain/DB тестов и все 4 E2E прошли. Чистый Compose с worker/PDF и metadata
backup/restore прошли; текущий экземпляр обновлён без потери записей. Реальные
provider-каналы по-прежнему требуют отдельной приёмки, как отмечено в таблице.

`npm.cmd run build`, затем `npm.cmd run test:phase-a` запускают A/B на собственной
случайной БД/очереди. Включены новые DB/domain-проверки и E2E портала, бюджета,
настроек уведомлений, report 403, RU/EN и мобильных длинных данных. Историческое
имя команды не ограничивает её только A. Отдельно typecheck, lint и clean Compose
acceptance, metadata backup с восстановлением. Итоговые результаты и дата
фиксируются в implementation-status.md после завершения прогона.

Для real-provider приёмки нужны отдельные тестовые SMTP/chat/webhook и Prometheus,
выбранные владельцем. Не подключать корпоративные серверы/S3 и не отправлять
сообщения в настоящие рабочие каналы без разрешения. SSH onboarding, S3 execution,
firewall и удалённые команды остаются C/D, не объявляются частью готового B.
