# InfraDeck 0.5.0 Beta 1

Version `0.5.0-beta.1`, tag `v0.5.0-beta.1`. Publication authorized on 2026-11-05. See [evidence](../release-preparation-status.md).

English is the default for login, invitations, setup and newly created workspaces.
Russian remains selectable. Existing workspace language preferences are preserved.

## Beta scope

Registry, projects, costs, imports, reports, roles/history, budgets/access and monitoring are available. Ordinary SSH/Sentinel remains enabled: a real server passed verified host-key/login, fresh CPU/RAM/load/disk and 120 CPU/RAM history points over one hour. This beta has no uptime/load guarantee.

Automatic S3 execution/restore and SSH key rotation are **disabled by default**. Server entry points and runner guards enforce this. Explicit opt-in for disposable authorized targets is documented in [operations](../operations.md#beta-experimental-operations). Queued backups/schedules pause while disabled; archives/history are retained. External destructive C acceptance remains open, outside the default beta scope. Firewall and managed updates are outside this release.

Prometheus/TLS/Alertmanager/SMTP/Telegram/Discord adapters are implemented. Full external provider delivery/failure/recovery matrices remain experimental; rely on individually configured and verified providers. A received Telegram test does not prove every incident/recovery path.

## Installation and recovery

The first release supports a source build with Node 24.18.0, npm 12.0.1 and Docker Compose. Local images target Linux amd64; runner shares worker. PostgreSQL 18.6 and Redis 7.2.11 persist in named volumes. Other image architectures remain untested. See [README](../../README.md) and [operations](../operations.md).

Registry images and installation without Node on the host are deferred. `deploy/compose.release.yaml` is a template for future published digest references. Use a fixed source archive/commit and set `SOURCE_URL` to corresponding public source before publishing. Preserve `.env`, ENCRYPTION_KEY and DB report artifacts. Reverting an image does not revert migrations. Metadata backup/recovery remains available independently of the disabled experimental S3 executor.

## Evidence and final decision

Typecheck, production build, CSV/XLSX and fail-closed gate tests passed. Isolated metadata upgrade/recovery, 14 migrations and focused C/DB tests passed. Final E2E and final-image Compose acceptance are recorded in the evidence log; prior runs do not imply that a newer image passed. Runtime advisories were fixed and notices are generated inside each image. Debian/browser license files remain in their distribution directories. History credential-pattern scan: 262 blobs, no matches for scanned key/token formats; this is not proof that every possible secret is absent.

The reviewable candidate consists of the local source manifest, source archive, checksums and source-build instructions. Commit/tag/public release and image publication are separate actions. Working servers are not destructive test targets.

C2 experimental limits: 16 MiB, 1000 files, 8 directories/8 databases, `/srv` only, 64 MiB physical size per PG database, matching pg_dump major, one active executor, single PUT. Ownership/permissions, empty directories and cluster globals are not preserved; versioned bucket history is not purged. SUCCESS means upload, not full application recovery. See [engine](../backup-engine.md).
