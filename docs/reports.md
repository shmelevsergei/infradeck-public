# Reports

Export permission is separate for VIEWER. Snapshot selection occurs on the server using the authenticated workspace and chosen project/environment/period. The worker validates the creator's current membership before generating an artifact. Downloads check current export permission and workspace, disable caching, return the correct content type and audit each download. Repeated downloads return the same saved bytes.

PDF uses Playwright Chromium and a trusted HTML template with escaped user text, embedded local Inter Cyrillic/Latin fonts, page numbers and blocked network requests. It contains a management summary, distinct current/planned infrastructure and currency costs, risk/control summary, upcoming work and a paginated resource appendix. It does not claim CPU metrics, a precise SLA, savings, or a baseline change when no source exists. IPs/domains are not in the management template by default.

XLSX uses ExcelJS, typed numbers/dates, frozen headers, column widths, filters and separate registry sheets. Text starting with spreadsheet formula triggers is escaped; known nested records are split into technical columns and record sheets, not executable formulas or JSON cells. Report byte artifacts are in PostgreSQL, so metadata backup includes both reports and job history.

Known resource specifications have readable technical columns (`server_vcpu`, `server_ramBytes`, engine/version, bucket/region/capacity, runtime and CIDR). Project links, allocations, backup results and restore verification remain separate worksheets, rather than JSON cells. ProjectCosts partitions effective monthly cost by explicit allocation percentages and includes an Unallocated remainder; the sum does not increase the workspace total. Currencies and planned/current amounts remain separate. Removing a project allocation moves that share to Unallocated in new reports; its previous allocation remains in deletion history.

The PDF contains the same project cost partition. Coverage uses applicable resources rather than all registry rows. The resource appendix and XLSX explicitly include HTTP health and FRESH/STALE/MISSING observation freshness; missing or expired results never become healthy by default. Upload a PNG/JPEG workspace logo in Settings (maximum 256 KiB) to embed it directly in the snapshot and PDF. Uploaded logos do not require network fetches. Existing local branding paths remain available for the application shell; the PDF uses the uploaded embedded image.

Period comparison uses a saved completed report snapshot at or before the requested period's start, with the same environment/project filters. Its actual timestamp is displayed; the comparison is between observations, not reconstructed continuous history. Resource additions/removals are computed from actual IDs, and previous/current cost totals are retained in the snapshot. Without such a baseline, the PDF/XLSX explicitly state that data is unavailable. This is not a claim of daily historical billing or SLA.

Artifact bytes are limited to 25 MiB per report; a larger artifact fails with a request to narrow filters. Upload limits for imports are independent (10 MiB compressed, 50 MiB ZIP expansion, 5000 rows and 100 columns). Report snapshots/artifacts and deletion history have no automatic time-based purge in Phase A. Workspace retentionDays currently applies only to HTTP observations. Plan storage capacity and administrative metadata backup retention accordingly: reports and embedded logos increase PostgreSQL database size, dump size and restore time. They are included in metadata backups, so there is no separate report-volume restore step. Automatic retention or external artifact storage is a future operational improvement, not an implemented control.
